# Proposal

## Why

Сейчас все запросы за время жизни сервера пишутся в одну папку `logs/<model>/<timestamp-запуска>`: логи разных клиентских сессий (диалогов) перемешаны, и нельзя восстановить один диалог целиком — prompt.log содержит полный повторяющийся промпт каждого запроса (в OpenAI-протоколе вся история пересылается заново), а сгенерированные ответы лежат отдельно в generated.log.

## What Changes

- Определение клиентской сессии по префиксу истории сообщений: входящий запрос, чьи messages являются продолжением (префиксом совпадают) уже виденной истории, относится к той же сессии; новый диалог — новая сессия. Первая имплементация ограничена клиентом opencode (user-agent / характерные заголовки); для прочих клиентов сессия не определяется.
- Если сессия определена: все логи запроса пишутся в подпапку сессии внутри папки запуска — `logs/<model>/<run-ts>/sessions/<YYYY-MM-DD_HH-MM-SS>_<session-id>/`. Имя папки начинается с даты-времени первого сообщения сессии.
- Файлы в папке сессии: `dialog.log` — единый лог диалога (входящие сообщения + сгенерированные ответы, по порядку); `http.log` (http io); `out.log` (generated); `app.log` (всё подряд, как сейчас).
- `prompt.log` упраздняется: полные повторные промпты больше не пишутся (его роль берёт dialog.log с новыми сообщениями); входящие сообщения логируются только инкрементально — только та часть messages, которая не была залогирована ранее в этой сессии.
- Если сессия определить не удалось — логирование полностью как сейчас (общая папка запуска, существующие файлы).

## Capabilities

### New Capabilities
- `session-logging`: определение клиентской сессии по истории сообщений и маршрутизация логов запроса в папку сессии (dialog/http/out/app), с fallback на текущее поведение.

### Modified Capabilities

(none)

## Impact

- `agent/common/log.py` — конфигурация логирования: обработчики и файлы логов (сейчас статический dictConfig на запуск сервера).
- `agent/server_openvino.py` (`setup_logging`) — создание папки логов.
- `agent/openai/engine_rest_common.py` — точка входа запроса, где доступна история messages (сейчас: лог `inbound history messages N`); здесь определяется сессия.
- Новый модуль отслеживания сессий (реестр сессий + сопоставление префиксов истории), общий для движков.
- Тесты: `agent/common/log_test.py`, новые тесты определения сессии.
